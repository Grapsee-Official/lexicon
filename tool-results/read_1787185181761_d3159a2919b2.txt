   626→Design Decisions (documented for the next agent):
   627→- RootScreen renders BottomNav conditionally (`if (activeTab != TabKey.HOME)`) instead of unconditionally. Rationale: HomeScreen.kt already renders its own BottomNav when activeTab == HOME (cannot modify HomeScreen per task rules), so an unconditional render would produce duplicate nav bars. Conditional rendering keeps a single source of truth per tab while respecting the "BottomNav always rendered" intent (it's always visible to the user, just rendered by different composables depending on the tab).
   628→- `NonHomeTab` wraps screen content in a `Box(Modifier.weight(1f).padding(bottom = 96.dp))`. The 96dp bottom padding matches HomeScreen's `PaddingValues(bottom = 96.dp)` and the web's `pb-24`, so the floating BottomNav never covers the last item of any scrollable screen.
   629→- AnimatedContent uses `contentKey = { it }` and a `label = "tabTransition"` for tooling clarity. Enter (220ms) is slightly slower than exit (180ms) so the incoming tab reads first.
   630→- Overlays (WordDetailSheet, SearchModal) are called unconditionally — the parallel agent's components are expected to observe `vm.uiState.selectedWord` / `vm.uiState.searchOpen` and animate themselves in/out. RootScreen does NOT wrap them in `AnimatedVisibility` to avoid fighting the components' own internal animations.
   631→- SEARCH tab branch in the `when` block falls back to `HomeScreen` defensively. The BottomNav's centre FAB calls `viewModel.openSearch()` which sets `searchOpen = true` (opening the SearchModal overlay) — it never actually sets `activeTab = SEARCH`. The fallback is just a safety net.
